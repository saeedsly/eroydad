## کاربرگ A — جدول مسیرها (Route Registry)

**وضعیت امروز:** `backend/routes/web.php` با ۴۴۰ خط و `backend/routes/admin.php` با ۵۹۰ خط؛ مسیرها به‌صورت ۷۵ شرط پراکندهٔ `if ($method === … && $path === …)` و `preg_match` نوشته شده‌اند. هیچ فهرست یکپارچه‌ای وجود ندارد، مسیر تکراری فقط با دید انسان قابل کشف است و مستندات API با کد هم‌خوان نگه داشته نمی‌شود.

**کار:**

1. تابع `route()` (در `backend/src/Http/routes.php`): هر شرط پراکنده به یک خط اعلانیِ خوانا تبدیل می‌شود:
   `if (route('GET', '/admin/events', $method, $path)) {` — برای مسیرهای الگویی: `route('GET', '#^/admin/events/(\d+)/edit$#', $method, $path, $m)`.
   **بدنهٔ هر مسیر عیناً بدون یک تغییر می‌ماند**؛ فقط سطرِ شرط عوض می‌شود. ترتیب اجرا، `exit`ها و افتادن به ۴۰۴ همان‌طور که هست می‌مانند.
2. هر فراخوانی `route()` جفت (method, pattern) را در جدول اجرا-زمان ثبت می‌کند → اسکریپت `tests/gen-routes-doc.mjs` از همین جدول/خط‌ها `docs/api/routes.md` را می‌سازد و در حالت `--check` آزمون می‌گیرد که سند با کد هم‌خوان است.
3. قاعدهٔ جدید تحلیل ایستا: جفت (method, pattern) تکراری نباشد؛ method فقط GET/POST باشد.
4. پارسر بخش «یکپارچگی پیوندها» در `tests/http-smoke-test.mjs` به خطوط `route()` جدید می‌خورد (و حالا می‌تواند به جدول واقعی تکیه کند، نه حدس از ifها).

**موفقیت:** پاسخ‌های سرور بایت‌به‌بایت قبل؛ سند مسیرها تولیدی و کنترل‌شده؛ فایل‌های route به‌جای جنگل if، فهرست اعلانی + بدنه.

## کاربرگ B — آزمون بیشتر (پرکردن `tests/{Unit,Security,Acceptance}`)

سه پوشهٔ خالی با سناریوهای واقعی پر می‌شوند؛ هر کدام یک runner دارد و به `tests/package.json` وصل می‌شود:

- **Unit** (`tests/Unit/*.php` + `tests/unit-run.mjs`): منطق خالص بدون HTTP — محاسبهٔ مالیات و `Money`، ماتریس مجوزها (`Permissions`)، اندیس ستون XLSX، قواعد محدودیت نرخ، ساخت ICS، پاک‌سازی متن (`SafeText`).
- **Security** (`tests/security-run.mjs`): مالکیت/IDOR (کاربر الف به بلیت/پرداخت/ثبت‌نام کاربر ب نمی‌رسد — ۴۰۴)، رد درخواست بدون CSRF، محدودیت نرخ ورود، باطل‌شدن نشست‌ها با «خروج از همه»، فرار ذخیرهٔ XSS و برگشت بی‌خطر آن در خروجی.
- **Acceptance** (`tests/acceptance-run.mjs`): سفر کامل «ثبت‌نام ← پرداخت آزمایشی ← بلیت ← کنترل ورود»، چرخهٔ تیکت پشتیبانی تا امتیاز، ورود کارکنان با سطر تکراری و گزارش خطا، و سالم‌بودن خروجی XLSX (باز کردن zip و درستی XML).

**موفقیت:** سه فرمان جدید سبز؛ `npm run all` بدون رگرسیون؛ شمارنده‌ها در `tests/README.md` به‌روز.

## کاربرگ C — مستندات (`docs/{api,architecture,deployment,payment}`)

امروز فقط `docs/security/release-checklist.md` سند دارد؛ چهار پوشهٔ دیگر خالی‌اند:

- **api/** — `routes.md` (تولیدشده از کاربرگ A، کنترل‌شده با آزمون) + `auth.md` (نشست، CSRF، ورود دومرحله‌ای، محدودیت نرخ، نقش/مجوز).
- **architecture/** — `overview.md` (لایه‌ها، چرخهٔ یک درخواست، نقشهٔ پوشه‌ها) + `data-model.md` (جدول‌های کلیدی و روابطشان).
- **deployment/** — `xampp.md` (نصب تمیز گام‌به‌گام + چک‌لیست دستی واقعی)، `linux.md` (چارچوب میزبانی + اجرای migration روی نصب موجود)، `backup.md` (پشتیبان و بازیابی).
- **payment/** — `sandbox.md` (سناریوها، گردش پرداخت، دفتر مالی، استرداد) + `money.md` (مالیات، انتخاب پرداخت‌کننده، ریز مبلغ).
- همه از `project/README.md` و `tests/README.md` پیوند می‌خورند؛ چک‌لیست انتشار دروازه‌های جدید را می‌پذیرد.

**موفقیت:** هر چهار پوشه سند اصلی دارند؛ پیوند از README کار می‌کند؛ `routes.md` با کد هم‌خوان است.

## کاربرگ D — موارد ۸۵ / ۸۶ / ۸۹ نقشهٔ راه

- **۸۵ — نصب تمیز روی XAMPP ویندوز:** آزمون خودکار `tests/clean-install-test.mjs`: از همان ZIPِ تحویلی استخراج می‌کند → روی دیتابیسِ تازه schema + migration را می‌راند → فرانت‌کنترلِ نسخهٔ استخراج‌شده را بالا می‌آورد → خانه/ورود/رویداد باید سبز شوند. راستی‌آزمایی روی ویندوز واقعی در sandbox ممکن نیست؛ چک‌لیست دستیِ گام‌به‌گام در `docs/deployment/xampp.md` می‌ماند و مورد `[~]` می‌شود (پیاده‌سازی‌شده، آزمون ماشینیِ نصب واقعی ندارد).
- **۸۶ — مرورگر و اندازه‌های صفحه:** تلاش برای Chromiumِ بسته‌بندی‌شده در npm (`@sparticuz/chromium` + `puppeteer-core` — فقط از `registry.npmjs.org` که مجاز است). اگر راه افتاد: `tests/browser-smoke.mjs` صفحه‌های کلیدی را در ۳۶۰×۷۴۰، ۷۶۸×۱۰۲۴ و ۱۲۸۰×۸۰۰ می‌سنجد (بی‌ابعادی افقی، کارکرد منو، خوانا بودن فرم) و به `all` وصل می‌شود. تک‌موتوره‌بودن صادقانه ثبت می‌شود → `[~]`.
- **۸۹ — بازبینی حقوقی شرایط استفاده و مالکیت:** پیش‌نویس `docs/legal/terms-fa.md` (مالکیت محتوا، مجوز کاربر، مسئولیت، داده‌های شخصی) و `docs/legal/privacy-fa.md`؛ صفحهٔ `/terms` موجود تکمیل می‌شود و صفحهٔ حریم خصوصی اضافه؛ آزمون وجود بخش‌های الزامی در هر دو صفحه. تأیید حقوقیِ انسانی خارج از محدوده است → `[~]`.
