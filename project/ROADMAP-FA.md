# برنامهٔ ۹۰ قابلیت ای‌رویداد

فهرست زیر در اسناد توسعه نگهداری می‌شود، نه در رابط کاربران. هر مورد عنوان کوتاه و وضعیت مستقل دارد؛ تغییرات هر فاز پیش از رفتن به فاز بعدی بازبینی می‌شوند.

## راهنمای وضعیت‌ها

وضعیت‌ها بر پایۀ آنچه مجموعهٔ آزمون همین مخزن واقعاً اثبات می‌کند نوشته شده‌اند (اجرا: `npm --prefix tests run …`؛ توضیح در `tests/README.md`):

- `[x]` پیاده‌سازی شده **و** در آزمون خودکار بررسی شده: یا رفتار سرویس روی PHP 7.4 + MariaDB واقعی (آزمون یکپارچه، ۱۵۶ بررسی) یا پاسخ HTTP واقعی (آزمون HTTP، ۱۴۰ بررسی) یا تحلیل ایستا.
- `[~]` پیاده‌سازی شده، اما فقط با تحلیل ایستا و بازبینی کد تأیید شده؛ آزمون زمان‌اجرا ندارد (معمولاً چون به مرورگر، دوربین، چاپ یا فایل واقعی نیاز دارد).
- `[ ]` پیاده‌سازی نشده.

> موارد ۸۵، ۸۶ و ۸۹ اکنون `[~]` هستند: بخش ماشینیِ آن‌ها آزمون خودکار دارد (استخراج واقعیِ بسته و نصب تمیز؛ Chromium واقعی در سه اندازهٔ صفحه؛ پیش‌نویس اسناد حقوقی + صفحهٔ `/privacy`) اما راستی‌آزمایی دستی ویندوز/مرورگرهای واقعی و تأیید حقوقیِ انسانی همچنان باز است.

## وضعیت این نوبت (بهبود چهاربخشی)

چهار کاربرگ هم‌زمان اجرا و هر کدام جداگانه کامیت شد؛ در مسیرشان **دو ایراد واقعی دیگر** پیدا و با آزمون پوشش داده شد:

**الف) جدول مسیرها (Route Registry)** — ۹۶ شرط پراکندهٔ `if ($method===…)` در `backend/routes/*.php` به خطوط اعلانیِ `route('GET', '/path', …)` تبدیل شد (بدنه‌ها عیناً ماندند؛ رفتار سرور بایت‌به‌بایت قبل). جدول اجرا-زمان + قاعدهٔ تحلیل ایستا برای مسیر تکراری/متد غیرمجاز + سند تولیدشدهٔ [`docs/api/routes.md`](docs/api/routes.md) با کنترل `--check` در آزمون‌ها.

**ب) آزمون بیشتر** — سه پوشهٔ خالی پر شد: `tests/Unit` (۵ فایل، ۵۱ بررسی: مالیات، مجوزها، اندیس XLSX، ICS، کد ملی)، `tests/Security` (۲۳ بررسی: مالکیت/IDOR، CSRF، XSS ذخیره‌شده، باطل‌شدن نشست، محدودیت نرخ)، `tests/Acceptance` (۳۳ بررسی: سفر فراگیر، سفر پرداختِ شکست←موفق، سفر مدیر با بازکردن واقعی zip/XML خروجی XLSX). همه به `npm run all` وصل‌اند.

**پ) مستندات** — `docs/api/{routes,auth}.md`، `docs/architecture/{overview,data-model}.md`، `docs/deployment/{xampp,linux,backup}.md`، `docs/payment/{sandbox,money}.md` و `docs/legal/{terms,privacy}-fa.md`؛ همه از README پیوند دارند.

**ت) موارد ۸۵/۸۶/۸۹:**
- **۸۵ نصب تمیز** `[~]`: `tests/clean-install-test.mjs` (۲۵ بررسی) بستهٔ ZIP واقعی را استخراج، روی دیتابیس تازه نصب و اجرا می‌کند؛ چک‌لیست دستی ویندوز در `docs/deployment/xampp.md`.
- **۸۶ مرورگر و اندازه‌ها** `[~]`: `tests/browser-smoke.mjs` (۱۹ بررسی) با Chromium واقعی ۱۳۱ (بدون CDN بیرونی) در ۳۶۰/۷۶۸/۱۲۸۰ چهار صفحهٔ کلیدی را می‌سنجد؛ تک‌موتوره‌بودن صادقانه ثبت است.
- **۸۹ بازبینی حقوقی** `[~]`: صفحهٔ `/privacy` اضافه و `/terms` تکمیل شد، اسناد `docs/legal/` نوشته شد؛ تأیید حقوقیِ انسانی باز است.

**دو ایراد واقعیِ کشف‌شده در همین نوبت (هر دو با آزمون پوشش‌دار):**
- [x] `GET /feedback/{id}` برای **همهٔ** کاربران ۵۰۰ می‌داد (ستون ناموجود `r.rating` در SELECT)؛ اصلاح شد و آزمون پذیرش/امنیت فرم بازخورد را می‌سنجد.
- [x] «ادامهٔ پرداخت آزمایشی» بعد از سناریوی ناموفق **همیشه خطا می‌داد** (`process()` سندِ `failed` را نمی‌پذیرفت) و کاربر در ثبت‌نام پولی گیر می‌کرد؛ اکنون سند ناموفق قابل تلاش دوباره است و سفر شکست←موفق در آزمون پذیرش پوشش دارد.

**لایهٔ آزمون و بسته:** `tests/package.json` فرمان‌های `unit`/`security`/`acceptance`/`browser`/`install:clean`/`routes`/`all` دارد؛ آزمون HTTP اکنون ۱۴۰ بررسی (شامل صفحه‌های `/terms` و `/privacy`)؛ بازرس بسته ۳۰ بررسی روی همان ZIP تحویلی.

## وضعیت این نوبت (ترمیم تاریخ، تم زمرد و طلا، ثبت‌نام سریع)

**سه ایراد واقعیِ کشف‌شده و بسته‌شده با آزمون مرورگر واقعی:**

- [x] باگ «تاریخ/ساعت معتبر نیست» در ساخت رویداد: تاریخ‌شمار در **دو جا** مقدار مخفی را خراب می‌ساخت (`hm[0]+':'+hm[1}` به‌جای `hm[1]+':'+hm[2}` → `10:00:10`)؛ هم اسکریپت اصلاح شد و هم سرور مقدار دارای ثانیه را نرمال می‌کند. پوشش: `tests/date-flow-browser.mjs` (۷ بررسی، سه مسیر واقعی) + ۳ تست واحد جدید.
- [x] فرم جلسات رویداد بدون اسپن خطا (`data-date-error`) بود و `setError` با `null` جاوااسکریپت را می‌شکست؛ اسپن‌ها اضافه و `setError` مقاوم شد.
- [x] اسکریپت بوت تم درون‌خطی بود و با `CSP: script-src 'self'` در مرورگر واقعی مسدود می‌شد؛ به `theme-boot.js` خودی منتقل شد.

**افزوده‌های این نوبت:**

- [x] ثبت‌نام سریع بدون ورود از لینک خود رویداد (`POST /events/{slug}/quick-register`) — سفر پذیرش E.
- [x] تم کاملاً تازهٔ «زمرد و طلا» (هدر شیشه‌ای تیره، قهرمان شفق‌دار، بخش تیره، پاورقی مرمر، فونت وزیرمتن واقعی) با اسکرین‌شات و آزمون مرورگر.
- [x] لایهٔ دوم CSRF: بررسی Origin روی همهٔ POSTها (۴۱۹ برای مبدأ بیگانه) + دو بررسی HTTP جدید.

## بخش‌های کد که با این فازها به‌روز می‌شوند

- رابط و منو: `frontend/views/layout.php`، `assets/css/design-system.css`، `assets/js/menu.js`
- دوره و پوستر: `database/schema.sql` و migration افزایشی، `backend/src/Events/EventService.php`، کنترلر `frontend/public/index.php`، فرم و کارت دوره، ذخیره‌سازی تصویر
- مبلغ و sandbox: schema، خدمات ثبت‌نام/بلیت، محاسبهٔ مالیات، رسید، گزارش مالی و قفل جلوگیری از پرداخت واقعی
- Excel: سرویس‌های ورود/خروجی، قالب‌ها، مجوزهای نقش، audit، آزمون فایل مخرب/خراب/تکراری و وابستگی محلی
- تحویل: تست PHP 7.4، XAMPP، راهنمای فارسی و ZIP بدون `.env`

> برای دیتابیس نصب‌شده از migration افزایشی استفاده می‌شود؛ `schema.sql` پایه روی دیتابیس دارای اطلاعات دوباره Import نمی‌شود. تمام فایل‌های رابط جدید باید محلی بمانند و به CDN وابسته نشوند.
