# PROJECT_DEPENDENCIES.md — وابستگی‌ها (مرحلهٔ ۱)

## ۱. وابستگی‌های اجرایی (Production) — **هیچ**

| ردیف | وضعیت |
|---|---|
| Composer / PHP packages | ❌ ندارد — کل backend با کتابخانهٔ استاندارد PHP 7.4 نوشته شده |
| فریمورک (Laravel/Symfony/…) | ❌ ندارد |
| CDN / فونت خارجی / Google Fonts | ❌ ندارد — همه local |
| سرویس بیرونی (SMS/ایمیل/درگاه زنده) | ❌ ندارد — اعلان درون‌برنامه‌ای؛ دروازه Sandbox |
| Node در استقرار | ❌ ندارد — فقط برای ساخت/تست |
| جاوا/کاتلین | ❌ ندارد |

**نتیجه:** استقرار فقط به **XAMPP (Apache + PHP 7.4 + MySQL/MariaDB)** نیاز دارد؛ ZIP تک‌فایلی همین را نصب می‌کند.

- نیازمندی: **Node ≥ 22.6** (ESM + `node:sqlite` ممکن است استفاده شود)
- تعداد فایل‌های تست/اسکریپت: ۱۵+ ابزار در `project/tests`
- **بدون اینترنت در اجرا**: همهٔ دارایی‌ها local

## ۳. مرورگرهای هدف (واقعیت پشتیبانی)

- ✅ Chromium-family: تست‌شده در دروازه (browser-smoke، contrast)
- ⚠️ Firefox/WebKit: پشتیبانی‌شده با vanilla CSS/JS اما **تست‌نشده** → فاز QA (Q3)

## ۴. سیستم‌عامل استقرار

- ✅ ویندوز + XAMPP: ZIP + نصب‌کنندهٔ `install-*.php` (E2E در دروازه)
- ✅ لینوکس: `docs/deployment/linux.md` موجود
- ⚠️ تست دستی ویندوز: `[~]` در نقشهٔ راه (تأیید دستی مانده)

## ۵. تصمیم معماری مبتنی بر وابستگی‌ها

نبودِ وابستگی اجرایی **محدودیت نیست، انتخاب است**: حفظ «بدون بازنویسی، بدون جایگزینی تکنولوژی»
(architectural_rule) یعنی تمام قابلیت‌های هدف (API، وب‌هوک، گردش‌کار، سازمان) باید با **همین
پشتهٔ PHP 7.4 + vanilla** پیاده شوند — دقیقاً همان کاری که تا امروز شده است.
