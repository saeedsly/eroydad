# TECHNICAL_DEBT.md — بدهی فنی واقعی (مرحلهٔ ۱)

> رصد کد + نقشهٔ راه ۹۰تایی. «بدهی» = چیزی که کار می‌کند اما برای مقیاس/نگهداری هزینه دارد.

## ۱. بدهی‌های معماری

| # | بدهی | هزینهٔ واقعی | اقدام هدف (بدون بازنویسی) |
|---|---|---|---|
| A1 | منطق کاری در سرویس‌ها + روترهای ضخیم درهم (بدون لایهٔ Application مستقل) | سختی تست واحدِ صرفِ منطق؛ تکرار شرط‌ها در routes | افزودن لایهٔ Application سبک در معماری هدف (مرحلهٔ ۰۳) — **بدون جابه‌جایی فریمورک** |
| A2 | `bootstrap.php` تک‌فایلی با توابع سراسری زیاد (headers, csrf, render, …) | پهنا؛ تغییر ریسک‌دار | استخراج هدرها/CSRF به کلاس‌های `Security` در همان پشته |
| A3 | بدون کار پس‌زمینه (cron/queue) — یادآوری روی دیدن صفحه | یادآوری فقط وقتی کاربر صفحه را دیده | سرویس زمان‌بند (cron سادهٔ PHP یا اسکریپت استقرار) + جدول job |
| A4 | بدون API عمومی؛ همه چیز HTML | یکپارچگی/اتوماسیون ممکن نیست | `/api/v1` با کلید API (مرحلهٔ ۱۰) |
| A5 | جداسازی واقعی «سازمان» وجود ندارد (organization_profiles تک‌سطحی) | معماری Multi-tenant سطح‌بندی باید بعداً با مهاجرت اضافه شود | مهاجرت افزایشی در مرحلهٔ ۰۵ |
| A6 | هم‌پوشانی schema.sql و migration 002 (D1) | دو منبع حقیقت | مرحلهٔ مهاجرت هدف: یک خط پایهٔ `000_base.sql` |
