# پشتیبان‌گیری و بازیابی

مرجع کد: `backend/src/Admin/BackupService.php`، جدول `backup_runs`، مسیر `POST /admin/system/backup` (مجوز `system.health`).

## ساخت پشتیبان

از پنل مدیر → «سامانه» → «پشتیبان‌گیری» (یا هر فراخوانی `BackupService::create($actorId)`):

1. همهٔ جدول‌ها را با `SHOW CREATE TABLE` + `SELECT *` به یک فایل SQL کامل تبدیل می‌کند (`SET NAMES utf8mb4`، خاموش‌کردن موقت `FOREIGN_KEY_CHECKS`).
2. فایل: `storage/private/backups/backup-YYYYmmdd-HHMMSS.sql` (پوشهٔ خارج از ریشهٔ وب؛ فقط با مجوز سرور).
3. در `backup_runs` ثبت می‌شود: نام فایل، اندازه، تعداد جدول، تعداد ردیف، **SHA-256**، وضعیت و سازنده — به‌علاوهٔ ردیف در `audit_logs` (`system.backup.created`).

## آزمون بازیابی (Verify)

دکمهٔ «آزمون بازیابی» روی هر پشتیبان، `BackupService::verify()` را می‌زند:

- سلامت فایل و هش را بررسی می‌کند؛
- یکی از جدول‌ها را به‌صورت آزمایشی در **جدول موقت** بازیابی و دوباره می‌خواند (`rehearse`)؛
- نتیجه (`ok`/`failed` + پیام) در `backup_runs.status` می‌ماند.

یعنی «فایل ساخته شد» با «بازیابی می‌شود» فرق دارد و هر دو در گزارش انتشار دیده می‌شوند.

## بازیابی دستی

```sql
-- روی دیتابیس خالی با همان نام (در XAMPP: phpMyAdmin → Import)
SOURCE /مسیر/backup-20260101-120000.sql;
```

یا `mysql -u USER -p erooydad < backup-….sql`. پس از بازیابی:

1. `php deployment/local-xampp/migrate.php` — مهاجرت‌هایی که بعد از تاریخ پشتیبان آمده‌اند اعمال می‌شوند (روی نصبِ هم‌سطح، چیزی اجرا نمی‌شود).
2. کنترل سلامت از پنل مدیر و ورود آزمایشی.

## نگهداری

- فایل‌های SQL در `storage/private/backups/` بمانند؛ **هرگز** به ریشهٔ وب منتقل نشوند.
- انتقال به بیرون سرور (به‌صورت رمزنگاری‌شده) بر عهدهٔ عملیات سرور است — این سند فقط بخش داخلی را پوشش می‌دهد.
- پاک‌سازی دادهٔ گزارش/نگهداری، موضوع `data_retention_log` و مجوز `settings.manage` است؛ پشتیبان‌ها را با آن اشتباه نگیرید.
- در چک‌لیست انتشار: «تازه‌ترین پشتیبان با وضعیت ok + آزمون بازیابی موفق» یک دروازهٔ جداگانه دارد.
