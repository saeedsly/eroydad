# ریز مالی: مبلغ پایه، مالیات و جمع

سند مکمل [`sandbox.md`](sandbox.md)؛ مرجع کد: `backend/src/Payments/Money.php`.

## قرارداد عددی

- واحد پول: **تومان**؛ همهٔ مقادیر `INT` صحیح (نه DECIMAL، نه ریال).
- درصد مالیات: `FLOAT` در `[0, 100]`؛ مقدار خارج از بازه در محاسبه محدود می‌شود.
- گرد کردن: `round(base × percent / 100)` — نیم‌بالا/پایین استاندارد PHP، بدون اعشار.

## فرمول

```
tax        = round(base × tax_percent / 100)
total      = base + (tax_payer == 'participant' ? tax : 0)
organizer  = (tax_payer == 'organizer' ? tax : 0)
```

| پرداخت‌کنندهٔ مالیات | فراگیر می‌پردازد | برگزارکننده می‌پردازد |
|--------------------|------------------|------------------------|
| `participant` (فراگیر) | پایه + مالیات | ۰ |
| `organizer` (برگزارکننده) | فقط پایه | مالیات |

برچسب فارسی: `Money::payerLabel()` — «فراگیر» یا «برگزارکننده»؛ نمایش مبلغ: `Money::format()` ( جداکنندهٔ هزارگان، بدون اعشار، پسوند «تومان»).

## این اعداد کجا نوشته می‌شوند؟

1. **رویداد** — `events.price_toman`, `events.tax_percent`, `events.tax_payer` (تنظیم مدیر هنگام ساخت/ویرایش).
2. **ثبت‌نام** — `registrations.amount_total_toman` در لحظهٔ ثبت‌نام (قفل‌شدن مبلغ رویداد در همان زمان).
3. **سند پرداخت** — `payments` پایه/مالیات/جمع و درصد و پرداخت‌کننده را **کپی** می‌کند؛ ویرایش بعدی رویداد روی اسناد قدیمی اثری ندارد.
4. **دفتر** — `payment_ledger` فقط مبالغ نهایی جابه‌جاشده را نگه می‌دارد.

## نمایش به کاربر (صفحهٔ رویداد و رسید)

- مبلغ پایه ← «مبلغ پایه»
- مالیات ← «مالیات (٪…)» + مبلغ
- پرداخت‌کننده ← برچسب «فراگیر»/«برگزارکننده»
- جمع ← «مبلغ قابل پرداخت» / جمع نهایی

پوشش آزمون: سناریوی پولی در `tests/http-smoke-test.mjs` (ریز مبلغ و مالیات روی صفحهٔ رویداد: ۲۵۰٬۰۰۰ + ۱۰٪ = ۲۷۵٬۰۰۰ با پرداخت‌کنندهٔ «فراگیر») و محاسبهٔ خالص در `tests/Unit/`.

## قواعد مرزی

- پایهٔ منفی ← صفر.
- درصد صفر ← بدون مالیات، جمع = پایه.
- `tax_payer` ناشناخته ← `participant` (محافظ در برابر دادهٔ خراب).
- لغو/استرداد: مبلغ سند تغییر نمی‌کند؛ وضعیت `refunded` و ردیف `refund` در دفتر اضافه می‌شود.
