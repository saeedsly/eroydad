# چک‌لیست امنیت پیش از انتشار

این فهرست باید پیش از هر انتقال به محیط عمومی پر شود. همهٔ بند‌ها با وضعیت
«باید دست‌کم یک بار در محیط مقصد بررسی شوند» نوشته شده‌اند؛ تیکت‌زدنشان در این
مخزن به‌معنای اجرای آزمون روی سرور مقصد نیست.

## ۱) رمزها و پیکربندی

- [ ] `APP_KEY`، `EMPLOYEE_HMAC_KEY` و `TICKET_SIGNING_KEY` روی سرور مقصد با `deployment/local-xampp/generate-secrets.php`
      تولید و در `.env` قرار گرفته باشند (مقادیر پیش‌فرض یا کپی‌شده از بستهٔ توسعه پذیرفته نمی‌شود).
- [ ] فایل `.env` بیرون از وب‌روت باشد؛ `.htaccess` بسته مسیرهای نقطه‌دار و `backend|database|deployment|storage|tests|frontend/views`
      را می‌بندد، اما در آپاچی مقصد `AllowOverride` و `mod_rewrite` فعال بودن را بررسی کنید (در nginx این قواعد اجرا نمی‌شوند).
- [ ] `APP_DEBUG=false` باشد.
- [ ] حساب MySQL برنامه حداقل دسترسی لازم را داشته باشد و `root` بدون رمز نباشد.
- [ ] رمزهای مدیر نمونهٔ ساختگی در بستهٔ توسعه روی سرور واقعی استفاده نشده باشد.

## ۲) انتقال‌امن و هدرها

- [ ] TLS فعال و `http://` به `https://` ریدایرکت شود (هدر `Strict-Transport-Security` پیشنهاد می‌شود).
- [ ] هدرهای امنیتی `bootstrap.php` (CSP، `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`،
      `Referrer-Policy`، `Permissions-Policy`) در پاسخ‌های واقعی سرور هم دیده شوند.
- [ ] رفتار نشست همان است که `backend/bootstrap.php:81-101` می‌سازد و باید در پاسخ سرور مقصد هم دیده شود:
      `use_strict_mode=1`، `use_only_cookies=1`، `HttpOnly`، `SameSite=Lax`، `Secure` خودکار وقتی `HTTPS` روشن است،
      بی‌اعتباری پس از ۳۰ دقیقه بی‌کاری و حداکثر ۱۲ ساعت عمر نشست (با `session_regenerate_id`).
- [ ] CSP در سرور مقصد بدون `unsafe-eval` کار کند؛ `style-src 'unsafe-inline'` تنها برای استایل‌های درون‌خطی رابط است.

## ۳) داده شخصی

- [ ] کد ملی خام ذخیره نمی‌شود؛ فقط HMAC با `EMPLOYEE_HMAC_KEY` (بازبینی: `employee_allowlist`).
- [ ] خروجی‌های Excel برای مدیر رویداد با شمارهٔ موبایل پوشیده (`maskPhone`) تولید می‌شوند؛
      فقط مدیر سامانه شمارهٔ کامل می‌گیرد.
- [ ] صفحۀ خروجی شرکت‌کنندگان و فایل‌های دانلودی پس از استفاده پاک شوند؛ retention برای لاگ‌ها و
      اعلان‌های خوانده‌شده در `/admin/system` اجرا شده باشد.
- [ ] پیوست‌ها و پوسترها بیرون از وب‌روت (`storage/private`) نگهداری و با مسیر مستقیم قابل دانلود نباشند.

## ۴) دسترسی‌ها

- [ ] ماتریس نقش و مجوز در `/admin/roles` بازبینی و تغییرات لازم ثبت شده باشد.
- [ ] `event_admin` فقط رویدادهای خودش را می‌بیند/ویرایش می‌کند (آزمون یکپارچه §۱۵ همین را می‌سنجد).
- [ ] مسیرهای حساس (تعلیق حساب، ابطال نشست، بازصدور بلیت، حذف پیوست/جلسه) با تأیید دو مرحله‌ای انجام می‌شوند.
- [ ] ورود دومرحله‌ای برای مدیران فعال و کدهای بازیابی در `/admin/password-resets` بی‌استفاده نمانده باشند.

## ۵) پایداری

- [ ] پشتیبان‌گیری (`/admin/system` → ساخت پشتیبان) در بازهٔ زمان‌بندی‌شده اجرا شود و
      `verify` روی دست‌کم یک فایل موفق باشد؛ فایل پشتیبان در جای امن خارج از وب‌روت نگه داده شود.
- [ ] اجرای مهاجرت‌ها روی کپی دیتابیس مقصد آزمایش و `schema_migrations` بررسی شود.
- [ ] پس از هر انتشار، مقدار `CACHE_NAME` در `frontend/public/sw.js` (پیش‌فرض `erooydad-static-v1`) عوض شود؛ در غیر این صورت مرورگر فایل‌های کهنه را نگه می‌دارد. پوشهٔ `storage/private` (پوستر و پیوست) و `storage/private/backups` باید بیرون از دسترس وب بمانند.
- [ ] نرخ محدود ورود/ساخت حساب پس از انتشار پایش شود (`/admin/rate-limits`): در بازۀ ۱۵ دقیقه‌ای، ورود با ۸ تلاش
      ناموفق برای هر شماره یا ۳۰ تلاش برای هر IP موقتاً بسته می‌شود و ساخت حساب با ۵ درخواست برای هر شماره یا
      ۲۰ درخواست برای هر IP رد می‌شود (`backend/src/Security/RateLimiter.php`)؛ قفل دائمی حساب سیاست نشده است.

## ۶) بازبینی نهایی

- [ ] بازبینی حقوقی متن `شرایط استفاده و مالکیت` و `حریم خصوصی` انجام شده باشد (فقط متن پایه در بسته است).
- [ ] آزمون مرورگر واقعی (Chrome/Firefox/Safari موبایل و دسکتاپ) برای منو، تاریخ شمسی، اسکن QR و چاپ گواهی انجام شود.
- [ ] نصب تمیز روی XAMPP ویندوز مقصد با همین بسته آزمایش و نتیجه در سند استقرار ثبت شود.
- [ ] نتیجهٔ `npm --prefix tests run analyze`, `lint`, `schema`, `migration`, `migration:runner`, `integration`, `http`, `datepicker` پیوست گزارش انتشار شود.
- [ ] بستهٔ انتشار با `npm --prefix tests run package` ساخته شود و `npm --prefix tests run zip` روی همان فایل سبز باشد (نبود راز/`node_modules`/دادهٔ کاربری، بودن فایل‌های لازم نصب، نبود ارجاع CDN).

> این چک‌لیست جای ممیزی امنیتی حرفه‌ای را نمی‌گیرد؛ برای محیط سازمانی، بازبینی امنیتی مستقل و
> آزمون نفوذ پیشنهاد می‌شود.
